# 운영자 계정 삭제 절차 (L2 — 만 14세 미만 계정 등) v1

> AUTH-GA-TRANSFER-BASIS-AND-REGRESSION-GATES-V1 (2026-09-29), 증거 기준 보강 GA-CONSENT-AND-AUTH-WORDING-CLOSEOUT-V1(Owner L2 채택). Auth 브랜치 전용 — Production 에는 Auth 출시와 함께 들어간다.
> 처리방침 제13조 L2 문장("만 14세 미만의 이용자가 계정을 만든 사실을 알게 되면 해당 계정과 계정에 연결된 정보를 지체 없이 삭제합니다")을 실제로 지킬 수 있게 하는 절차다.

## 왜 별도 경로가 필요한가

본인 삭제(`POST /api/account/delete`)는 **그 계정의 이번 세션 재로그인**(amr 시각·session_id 결속 intent)이 있어야 작동한다. 운영자는 이용자의 세션을 가질 수 없으므로 그 API 를 대신 실행할 수 없다.
그래서 `POST /api/admin/account-delete` 를 두었다. 삭제 본문은 본인 삭제와 **같은 모듈**(`functions/_lib/account-purge.ts`)이라 삭제 범위·순서·보존 계약이 동일하다.

## 절차

| 단계 | 누가 | 무엇을 |
|---|---|---|
| 1. 신호 수신 | Owner(운영자) | support@gokoreamate.com 메일 또는 사이트 문의 양식(관리자 문의 목록). 본인·보호자·제3자 누구의 제보든 받는다 |
| 2. 계정 특정 | Owner | Supabase 대시보드(Production → Authentication → Users)에서 **이메일로 검색 → 사용자 UUID**. 제보에 계정 이메일이 없으면 제보자에게 "로그인에 쓴 Google 계정 이메일"을 묻는다. 없거나 일치 계정이 없으면 3-c |
| 3-a. 계정 주인 본인 확인 | Owner | 삭제 전에 **대상 계정의 이메일 주소로** 확인 메일을 보낸다(support@ 에서 발송). 제보 메일이 그 계정 이메일에서 왔으면 이 단계는 끝난 것으로 본다. **제보자 이메일이 계정 이메일과 다르면(보호자·제3자) 제보만으로 삭제하지 않는다** |
| 3-b. 만 14세 미만 사실 확인 — 아래 중 하나 | Owner | ① 계정 이메일에서 온 본인 진술(만 14세 미만이라고 밝힘) ② 계정 이메일로 보낸 확인 메일에 계정 주인이 만 14세 미만임을 인정하는 회신 ③ 보호자 제보 + 계정 이메일로 보낸 확인 메일에 대한 계정 주인의 삭제 동의 회신 ④ 그 계정이 스스로 공개한 콘텐츠·메모에 만 14세 미만임을 밝힌 내용(화면 캡처로 근거 보관, 개인정보는 기록에 옮기지 않음). **나이 증명 서류는 요구하지 않는다**(추가 개인정보 수집이 된다) |
| 3-c. 확인이 안 될 때 | Owner | 계정 주인이 확인 메일에 답하지 않고 ④도 없으면 **삭제하지 않고** 그 사실을 제보자에게 회신·기록한다. 계정이 없으면 "해당 이메일의 계정이 없습니다"로 회신하고 비로그인 이용은 아래 '한계' 안내. 모호한 경우 삭제보다 보존 쪽으로 판단한다(삭제는 되돌릴 수 없다) |
| 4. 삭제 실행 | Owner | 아래 요청 1회. 응답 `ok:true` 확인. 실패(`delete_failed`, `stage`)면 같은 요청을 다시 보내면 남은 단계부터 이어진다 |
| 5. 회신 | Owner | 제보자에게 삭제 완료 회신(법정 요청이면 10일 이내) |
| 6. 기록 | Owner | 아래 '처리 기록' 표에 날짜·사유 분류(under_14 등)·결과만 기록. 이메일·이름·UUID 는 기록하지 않는다 |

```bash
# ADMIN_KEY 는 Production 환경변수 값. 명령 기록에 남지 않게 입력한다.
curl -X POST https://gokoreamate.com/api/admin/account-delete \
  -H "content-type: application/json" -H "x-admin-key: $ADMIN_KEY" \
  -d '{"userId":"<UUID>","reason":"under_14","confirm":"DELETE <UUID>"}'
```

- `reason`: `under_14` · `legal_request` · `other` 중 하나.
- `confirm` 은 `DELETE ` 뒤에 같은 UUID(소문자) — 다르면 400 `confirm_mismatch` 로 아무것도 지우지 않는다.
- 응답: 200 `{ok:true, deleted:{…건수}}` · 401(키 없음·틀림) · 400(입력) · 404 `not_found`(계정 없음 또는 이미 삭제) · 503(조회·삭제 실패, 재시도 가능).

## 지우는 것 / 남는 것 (본인 삭제와 동일)

- 지움: 계정 기기들의 여행·기록·사진(Storage 먼저) · 나의 장소(사진) · 저장·좋아요·싫어요·장소 좋아요 · 도움됨·이벤트 반응·조회 기록·AI 생성 기록 · 장소 제보(발행 연결된 것 제외) · 서버 draft · 기기-계정 연결 · 동의 기록(CASCADE) · 로그인 계정(마지막).
- 남음: 익명 활용 집계(place_usage)·공유 원장(share_events) — 개인을 가리키지 않는 숫자, 타인이 이미 복사한 여행(원본 연결만 끊김), 발행된 장소 제보의 발행 결과.

## 한계 (약속하지 않는 것)

- **나이를 확인하지 않는다.** 가입 시 "만 14세 이상" 자기 확인뿐이다. 거짓으로 체크한 경우 제보가 없으면 알 수 없다. 자동 연령 검증·자동 삭제는 없다.
- **비로그인 이용은 사람을 특정할 수 없다.** 기기 식별자로만 저장되므로 운영자가 이름·이메일로 찾아 지울 수 없다. 그 기기에서 이용자(또는 보호자)가 여행 삭제로 직접 지우도록 안내한다. 공개된 Story 는 링크를 받으면 관리자 검수(`/api/admin/story-moderation`)로 **공개를 내릴 수 있지만** 이는 삭제가 아니다.
- 계정 주인 확인은 계정 이메일로의 메일 왕복뿐이다. 보호자·제3자의 제보만으로는 계정 주인과 나이를 모두 확인할 수 없으므로 3-a·3-b 없이 삭제하지 않는다 — 이 때문에 계정 주인이 응답하지 않으면 만 14세 미만 계정이 남을 수 있다(남는 한계).
- 이 절차와 증거 기준이 법 제22조의2 등 관련 법의 요구를 충분히 충족하는지는 **법률 해석을 확정하지 않았다** — 운영 기준으로 둔다.

## 실행 가능 조건

- Production 환경변수: `ADMIN_KEY`·`SUPABASE_SERVICE_ROLE_KEY`·`MYTRIP_HASH_SECRET`·`NEXT_PUBLIC_SUPABASE_URL` 모두 secret 으로 설정돼 있음(2026-09-29 이름·유형만 조회, 값 미출력). 기존 관리자 경로에 키 없이 요청 → 401(키 활성). **Auth 출시 시 환경변수 추가·변경 불필요.**
- 이 경로는 Auth 코드와 함께 배포된다 — 현재 Production 에는 없다(405).
- Preview 에는 `ADMIN_KEY` 가 없어 503(`Admin endpoint not configured`) — 차단 동작이며 삭제 실패가 아니다. 실제 삭제 PASS 는 아래 Staging 기록.
