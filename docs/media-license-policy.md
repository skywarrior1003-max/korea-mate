## 1. 왜 이 정책이 존재하는가

> **공식 홈페이지에 이미지가 있다는 것이 상업적 재사용 허가를 의미하지 않는다.**

GoKoreaMate는 한국 여행 플랫폼으로서 장소·행사 이미지를 서비스에 노출합니다.  
잘못된 이미지 사용은 **저작권 침해 소송**으로 이어질 수 있으며, 이는 서비스 운영 자체를 위협합니다.

이 정책은 그 리스크를 원천 차단하기 위한 **법적 방어막**입니다.

---

## 2. 핵심 원칙 3가지

### 원칙 1: 라이선스 없으면 등록 불가

```
media_licenses.license_id → place_media.license_id (NOT NULL)
```

`place_media` 테이블의 `license_id`는 NOT NULL입니다.  
라이선스가 확인되지 않은 이미지는 **DB에 등록 자체가 불가능**합니다.

### 원칙 2: 상업적 사용 불가 라이선스는 앱 노출 불가

```sql
-- gokoreamate.com 앱 이미지 조회 시 반드시 이 조건 포함
WHERE pm.admin_status = 'approved'
  AND ml.commercial_use_allowed = true
```

`commercial_use_allowed = false`인 라이선스에 묶인 이미지는  
DB에 존재하더라도 **절대 앱 화면에 노출하지 않습니다.**

### 원칙 3: 관리자 승인 게이트 필수 통과

```
이미지 등록 → admin_review_queue → 관리자 검토 3단계 → approved → 앱 노출
```

모든 이미지는 `admin_status = 'approved'` 전까지 앱에 나타나지 않습니다.

## 4. 이미지 등록 워크플로우

```
[1단계] 이미지 후보 발견
         │
         ▼
[2단계] 라이선스 유형 확인
         │
         ├─ commercial_use_allowed = true → 등록 진행
         └─ commercial_use_allowed = false → 등록 중단
         │
         ▼
[3단계] media_licenses 테이블에 license_id 존재 확인
         → 없으면 먼저 라이선스 등록 (verified_at 기록 필수)
         │
         ▼
[4단계] place_media에 이미지 등록 (admin_status = 'pending' 자동 설정)
         │
         ▼
[5단계] admin_review_queue에 검토 요청 생성 (3단계 순차 검토)
         │
         ├─ license-verify  : 라이선스 내용 재확인
         ├─ place-match     : 올바른 장소에 연결됐는지 확인
         └─ content-check   : 이미지 내용 적절성 확인
         │
         ▼
[6단계] 모두 통과 → admin_status = 'approved'
         │
         ▼
[7단계] 앱 화면에 이미지 노출
```

## 5. 라이선스 마스터 분리 설계 이유

`media_licenses`를 `place_media`와 분리한 이유:

| 이유 | 설명 |
|------|------|
| **재사용** | "공공누리 1유형"은 수백 장의 이미지가 동일 license_id를 참조. 매번 재입력 불필요. |
| **일괄 업데이트** | 라이선스 조건이 변경되면 `media_licenses` 1행만 수정하면 연결된 모든 이미지에 반영. |
| **상업 사용 차단** | `commercial_use_allowed = false`로 바꾸는 순간 연결된 모든 이미지가 앱에서 즉시 숨김. |
| **감사 추적** | `verified_at`, `verified_by`로 누가 언제 라이선스를 확인했는지 기록. |

## 6. place_match_logs — 매칭 이력 보존 이유

이미지를 장소에 연결할 때 "왜 이 사진이 저 장소에 붙었지?"를 나중에 추적하기 위해 `place_match_logs`를 유지합니다.

| match_method | 신뢰도 | 설명 |
|---|---|---|
| `api-id` | ★★★★★ | API가 제공한 고유 ID로 직접 연결 — 가장 신뢰도 높음 |
| `manual` | ★★★★☆ | 운영자가 직접 확인하여 연결 |
| `coordinate` | ★★★☆☆ | GPS 좌표 근접성으로 자동 매칭 |
| `name-exact` | ★★☆☆☆ | 장소명 정확 일치 — 동명 장소 충돌 위험 |

**이름만으로 연결하는 것은 금지합니다.** 동명이인 문제처럼 다른 장소에 사진이 연결될 수 있습니다.

## 7. admin_review_queue — 법적 승인 게이트

이 단계를 건너뛰고 이미지를 노출하는 것은 **절대 금지**입니다.

| 검토 유형 | 순서 | 확인 내용 |
|-----------|------|----------|
| `license-verify` | 1 | 라이선스 내용이 실제로 상업적 사용을 허가하는가? |
| `place-match` | 2 | 이미지가 올바른 장소·행사에 연결됐는가? |
| `content-check` | 3 | 이미지 내용이 서비스에 적절한가? (민감 내용 없는지) |

## 10. 시각 표현(Expression) 독창성 — Trip Cover 기준

**2026-07-26 확정.** 1~9절이 다루는 것은 **자산(asset) 라이선스** — 어떤 사진을 등록·노출할 수 있는가다.
이 절이 다루는 것은 **표현(expression) 복제** — 다른 앱의 화면 구성을 얼마나 따라가도 되는가다.
둘은 별개의 위험이며, 자산이 깨끗해도 표현을 복제하면 문제가 된다.

### 10.1 참고 이미지의 지위

Trip Cover 참고 이미지 4장(Polarsteps 스토리·공유 카드, Stippl 저널, My Trips 리스트)은
**시각 품질과 여행 기록 감성을 이해하기 위한 moodboard**다. **특정 앱 화면의 설계도가 아니다.**

### 10.2 수용하는 추상 원칙 (기능 유사성 — 허용)

- 사진 중심의 여행 기록
- 개인 여행 일기·앨범 표지 감성
- 여행 제목·기간·장소의 세련된 정보 계층
- 사진·지도·여행 사실을 조합하는 방식
- SNS에 저장·공유하고 싶은 완성도
- My Trips가 개인 여행 앨범처럼 보이는 방향

### 10.3 복제 금지 (표현 복제 — 불허)

```
- 정확한 화면 레이아웃과 요소 위치
- 동일한 여백·비율·크기 체계
- 동일한 글꼴·타이포그래피 계층
- 동일한 색상·그림자·배경 질감
- 동일한 지도 선·핀·경로 표현
- 동일한 원형 사진·폴라로이드 배치
- 동일한 아이콘·버튼·문구
- 동일한 애니메이션·화면 전환
- 참고 앱의 로고·상표·일러스트·화면 캡처 사용
- 참고 이미지를 픽셀 단위로 재현하는 구현
```

### 10.4 GoKoreaMate 고유 표현으로 대체한다

- **Coral·Ink·Neutral** 브랜드 체계
- 사진을 살리는 **자체 그라데이션**
- **여행 스탬프·Day 리본** 등 독자적 장식 언어
- **Copied·Helpful** — 우리만의 성과 지표
- 사회적 지표가 0일 때는 **실제 여행 사실**(days·places·neighborhoods) 표시
- `Shared by a GoKoreaMate traveler` 수준의 **사용자 콘텐츠 표기**
- **커버 생애주기** — 여행 전 장소 사진 → 여행 중·후 개인 사진
- 공개 일정이 복사되어 새 여행으로 이어지는 **제품 순환**

### 10.5 디자인 원칙

- 참고 앱을 보지 않아도 **GoKoreaMate 제품 논리만으로 디자인을 설명할 수 있어야 한다.**
- 특정 앱의 브랜드를 가렸을 때 그 앱 화면으로 오해할 정도면 **재설계한다.**
- **사진이 텍스트보다 먼저 보여야 한다.**
- 관리자 카드·일반 정보 카드·광고 배너처럼 보이면 안 된다.
- 세련됨은 유지하되 GoKoreaMate만의 편집 디자인으로 재해석한다.
- 지도형은 사진형의 복제·대체가 아니라 **V2의 별도 템플릿**이다.

### 10.6 UI 구현 후 필수 검토 5문항

| # | 질문 | 통과 기준 |
|---|------|-----------|
| 1 | 참고 앱 로고를 가려도 그 앱 화면으로 오해할 만큼 유사한가? | **NO** |
| 2 | 사진·제목·지도·통계의 위치가 참고 화면과 거의 같은가? | **NO** |
| 3 | 동일한 폰트·색상·아이콘·그림자·폴라로이드 구성을 썼는가? | **NO** |
| 4 | GoKoreaMate 제품 논리만으로 디자인 선택을 설명할 수 있는가? | **YES** |
| 5 | Copied·Helpful·커버 생애주기 등 고유 요소가 시각적으로 드러나는가? | **YES** |

**1~3 중 하나라도 명확히 YES이거나, 4~5 중 하나라도 NO이면 시각 설계를 수정한다.**
이 검토는 Trip Cover 구현 프롬프트와 UI 검증 단계에 계속 적용한다.

### 10.7 균형

- 참고 이미지의 **방향성과 세련됨은 유지**한다.
- 저작권 우려를 이유로 **개인 사진 중심 제품 방향을 축소하지 않는다.**
- 반대로 "감성만 참고했다"는 이유로 **구체적 화면 표현을 복제하지 않는다.**
- **기능 유사성과 표현 복제를 구분한다.**

> 개인 Memory 사진은 7절 각주대로 이 문서의 **자산 라이선스** 적용 대상이 아니지만,
> 그 사진을 공개 커버로 전환할 때의 동의·공개 경계는 별도 기준을 따른다.
