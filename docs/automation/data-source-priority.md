# 데이터 출처·품질 우선순위 원칙

> **적용 범위**: 공공데이터와 기존 기본 원천 데이터를 **비교·병합·교체 판단**할 때.  
> **우선순위 1순위**: 최신성 (수정일 기준) — 운영 사진 선정 기준과 다름.  
> 운영 사진 선정 기준(장소 일치도 우선)은 `image-curation-rules.md` 참조.

---

## 원천 역할 분류

| 역할 | 원천 | 설명 |
|------|------|------|
| 기본 원천 (primary) | 도시 공식 관광사이트 | 현지 최신 정보 기준 — 자동 교체 대상 아님 |
| 보완 원천 (supplementary) | 한국관광공사·공공데이터포털 API | 누락·무이미지·권리문제 보완 및 교차검증 |

도시별 공식 원천은 `tourapi-nightly-config.json`의 `cities.{city}.primarySource`에 설정값으로 지정한다.

## 보완 원천 내부 결합 방식

공공데이터 엔드포인트는 경쟁 관계가 아니라 역할별로 결합한다.

| 역할 | 엔드포인트 예시 |
|------|----------------|
| 목록 수집 | areaBasedList2, galleryList1 |
| 상세 보완 | detailCommon2, detailIntro2 |
| 증분 갱신 | areaBasedSyncList2, gallerySyncDetailList1 |
| 검색 보완 | searchKeyword2, gallerySearchList1 |

## 데이터 선택 기준 (비교 시 적용 순서)

새로 수집한 공공데이터와 기존 기본 원천 데이터가 충돌할 때, 출처명만으로 결정하지 않고 아래 기준을 순서대로 비교한다.

1. **최신성** — 수정일(modified_at) 기준 최신 데이터 우선
2. **장소 일치도** — 제목·좌표·주소 일치 정도 (매칭 score 참조)
3. **데이터 완전성** — 필수 필드(제목·좌표·이미지 URL) 채움 비율
4. **이미지 품질** — 해상도·포맷 유효성 (기술 스캔 결과 참조)
5. **권리·출처 상태** — KOGL 1유형 > KOGL 3유형 > review_required > unknown
6. **URL 접근 가능성** — 기술 스캔에서 access_failed이면 감점
7. **서비스 활용 적합성** — Trip Cover 크기 요건·CORS 제한·프록시 필요 여부

## 자동 교체 금지 원칙

- 새로 수집된 공공데이터라는 이유만으로 기존 기본 원천 데이터를 자동 교체하지 않는다.
- 기본 원천에 문제가 있거나(access_failed, 권리 unknown, 무이미지) 보완 원천이 위 7개 기준에서 명확히 우수할 때만 **교체 후보**를 생성한다.
- 교체 후보는 `operational_image_decision=replace_candidate`로 분리하고 사람 승인 후 적용한다.

## 충돌 처리

- 출처 충돌 시 기존 정본을 덮어쓰지 않는다.
- 비교 결과와 선택 근거(위 7개 기준별 판정)를 보고서·로그에 기록한다.
- 자동 선택이 불가능하면 `review_required`로 분리하고 계속 진행한다.
- 공공데이터 수정일이 기본 원천보다 오래되면 `older_than_primary_source`를 기록한다.

## Validation Gate 적용

다단계 파이프라인의 각 게이트에서 아래 항목을 추가로 검증한다.

- 매칭 단계: 매칭 결과가 기존 기본 원천 데이터를 덮어쓰는지 확인 → 덮어쓰기 감지 시 FAIL
- 집계 단계: 교체 후보 생성 건에 선택 근거 필드가 존재하는지 확인 → 누락 시 PASS_WITH_WARNINGS
- 대표 자산 선정: 선정된 자산의 권리 상태가 unknown이면 PASS_WITH_WARNINGS, access_failed이면 FAIL

## 수집 원천과 사용자 안내 원천 분리

> 이 절은 데이터 수집 우선순위(위 절)와 독립적이다. 데이터 병합·교체 판단에는 위 절의 7개 기준을 적용한다.

지역 관광사이트(VisitBusan 등)는 데이터 수집·발견 원천으로 활용한다. 사용자에게 표시하는 링크는 실제 정보를 직접 관리하는 원천을 우선한다. 직접 관리 링크가 없을 때만 수집 원천을 보조 링크로 사용한다.

### 카테고리별 사용자 안내 링크 우선순위

| 카테고리 | 1순위 | 2순위 | 보조 (직접 링크 없을 때) |
|---------|-------|-------|----------------------|
| 행사 | 행사 공식 홈페이지 | 주최기관·구청·공공기관 페이지 | 지역 관광사이트 |
| 음식점 | 공식 홈페이지·공식 블로그·공식 SNS | 지도 사업자 페이지 | 지역 관광사이트 |
| 관광지·산·공원 | 운영기관·지자체·공단·국립공원 공식 페이지 | 공공기관 보도자료 | 지역 관광사이트 |
| 선정·인증 정보 | 해당 기관(미쉐린·블루리본 등) 최신 공식 페이지 | — | — |

### 선정·인증 최신성 처리

- 최신 공식 확인이 안 된 선정·인증은 현재 배지로 표시하지 않는다.
- 확인 불가 항목은 과거 기록으로 보존하거나 `verification_required`로 처리한다.
- 취소·폐점·행사 종료 여부는 직접 원천에서 확인한다.

### 링크 필드 분리 원칙

- `source_url`: 데이터를 수집한 원천 페이지 URL
- `display_url`: 사용자에게 안내할 직접 관리 주체 URL
- 두 필드가 동일한 경우 `display_url_source: collection_source`로 기록한다.
